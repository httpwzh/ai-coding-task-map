# AI 编程任务图：第一版产品定义

## 1. 一页产品定义

**产品名称（暂定）**：AI 编程任务图（Code Task Map）

**目标用户**：独立开发者、个人兼职开发者，以及使用 AI 辅助编程但容易迷失在长对话中的人。

**用户问题**：一次 DSH 会话可能同时包含多个任务、分支、子代理、文件修改和测试结果。线性聊天记录能保存过程，却不容易回答“当前做到哪一步”“哪个分支失败了”“某个文件为什么被改动”。

**产品承诺**：把本地 AI 编程会话转换成一张可回看的任务地图，让用户用图形关系理解任务进度，并能从节点回到原始对话。

**第一版结果**：用户打开一个会话后，可以看到问题、分析、工具调用、文件和测试节点，按状态和分支阅读，点击节点查看详情，并导出为 PNG 或 Markdown。

**产品原则**：本地优先、只读安全、小步交付、先解决回顾问题，再考虑自动化和商业化。

**暂不处理**：账号、云同步、多人协作、企业权限、复杂后端、模型服务、拖拽工作流和 DSH 主界面重写。

## 2. MVP 功能清单

## 3. 技术实现方案

### 第一阶段：原型

- **前端**：React + Vite
- **图形库**：React Flow（当前包名为 `@xyflow/react`）
- **数据**：本地 JavaScript 固定 DSH 事件样例，不接数据库
- **状态**：React `useState`，只维护当前视图、选中节点和折叠节点
- **导出**：先导出 Markdown；PNG 使用 React Flow 的截图方案或浏览器截图能力

### 第二阶段：只读接入 DSH

1. 先阅读 DSH 会话、消息、工具调用、子代理和文件变更的数据结构。
2. 建立一个转换层，把 DSH 原始记录转换为统一的 `TaskNode` 和 `TaskEdge`。
3. 只在转换层适配 DSH，图形组件继续只认识自己的数据模型。
4. 用一份固定的真实会话样本做回归检查。
5. 通过插件 API 或只读文件接口读取数据，不修改 DSH 核心流程。

当前研究结果和字段映射见 [docs/dsh-data-mapping.md](dsh-data-mapping.md)。本阶段已经完成固定事件样例和转换层，真实会话读取仍放在下一阶段。

建议的节点模型：

```js
{
  id: 'event-001',
  type: 'question',
  title: '用户问题',
  status: 'success',
  timestamp: '2026-02-21T10:00:00Z',
  summary: '节点摘要',
  files: ['src/App.jsx'],
  conversationRef: 'message-001',
  parentId: null
}
```

边只表达关系：`sequence`、`branch`、`child-task`。不要把业务判断散落在画布组件里。

### 第一个真实接入的验收标准

- 能读取一段本地 DSH 会话
- 节点数量与原始事件数量可解释
- 每个节点都能回到原始记录
- 读取失败时给出明确错误，不影响 DSH 主程序
- 没有写入或修改 DSH 会话数据

## 4. 适合新手的 Vibe Coding 开发步骤

每一步只做一个可验证的变化，完成后提交一次 Git：

1. **保存当前版本**：初始化仓库，运行空页面，提交 `chore: initial app`。
2. **看懂假数据**：只修改 `src/data/sampleSession.js`，新增一个节点，确认页面能显示，提交。
3. **完成画布交互**：验证拖动、缩放、适应画布和选中节点，提交。
4. **完成详情面板**：点击不同节点，确认标题、状态、摘要和文件会变化，提交。
5. **完成折叠**：折叠一个分支，确认其子节点隐藏；再次展开，确认恢复，提交。
6. **完成线性视图**：同一份数据在列表中按时间显示，提交。
7. **加入导出**：先做 Markdown 导出，再做 PNG，分别提交。
8. **研究 DSH 数据**：只读源码和会话样本，写一份字段映射表，不急着改接入代码。✅
9. **做转换层**：加入 `src/data/normalizeSession.js`，用固定样本测试转换结果，提交。✅
10. **真实会话试用**：先只读一段会话，记录缺失字段和异常，修复一个问题再提交。

### Vibe Coding 检查习惯

- 每次让 AI 只改一个小目标，并先说明要改哪些文件。
- 修改前先看 `git diff`，修改后再看一次。
- 每完成一个可运行小功能就提交，提交信息写清楚行为变化。
- 出错时先保存错误信息、复现步骤和最近一次提交，再让 AI 分析。
- 不接受“顺便重构全部代码”的修改，除非你能解释每个文件的作用。
- 任何接入真实数据的改动，都要先确认是只读路径。

## 5. 试用和商业验证

先邀请 5～10 位使用 AI 编程的独立开发者，观察他们是否会在任务中途打开任务图，以及他们最常点击哪类节点。只有当用户明确愿意为回顾、搜索、自动总结或历史记录付费时，再确定 Pro 功能。

早期可测试一次性购买 49～99 元、支持者价 29～49 元，以及 199～999 元的安装配置或定制服务。订阅制和团队版放到出现稳定使用频率之后。
